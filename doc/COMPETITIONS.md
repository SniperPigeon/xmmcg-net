# 比赛管理与换届

直接访问 `/admin/`，在「比赛」中管理各届比赛。前台个人中心不再提供后台跳转链接。

## 新建比赛

1. 点击「添加比赛」，填写比赛名称、投稿/评分开关、每谱目标评分数、满分和每人真爱票上限。
2. 可选「复制配置来源」，沿用上一届的开关与评分参数；勾选「同时复制阶段模板」后，只复制阶段，不复制投稿、抽选结果、评分任务或成绩。复制的阶段默认停用，日期仍为原日期，需要调整。
3. 保存后为「筹备中」。在比赛详情点击「添加比赛阶段」或「比赛阶段」设置日程：
   - 没有歌曲上传与抽选阶段：歌曲上传、报名和抽选全部关闭。
   - 没有投稿或评分阶段：对应功能仅由本届的「允许投稿」「允许评分」开关控制。
   - 创建了投稿或评分阶段：还必须满足阶段已启用且处于指定时间内。
4. 确认配置后，在比赛详情点击「启用比赛」并确认。全站同时只能有一届进行中的比赛；已有比赛进行中时，必须先归档它。

启用后，首页时间轴、投稿列表、歌曲素材与抽选结果、评分任务、真爱票额度和投稿统计均只使用本届数据。用户及大小号绑定、个人资料、公告和 Banner 继续全站共用。

## 合作投稿与名额

比赛后台提供以下配置，复制比赛配置时也会一起复制：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| 允许合作谱面 | 开启 | 关闭后仅接受独立投稿 |
| 合作谱师需先授权 | 开启 | 开启时，必须先取得对应上传账号的授权；可按比赛需要关闭 |
| 每个账号或身份最多参与谱面数 | 1 | 独立投稿与合作投稿共用名额；0 为不限 |
| 投稿名额计算方式 | 每个账号独立计算 | 大号和每个小号各有自己的名额；也可配置为整组账号合并计算 |

默认合作流程：

1. 合作谱师登录「谱面投稿」页面，在「授权合作投稿」中搜索实际上传者的账号并授权。
2. 上传者在投稿表单中选择已授权的合作谱师，可以选择多人，再上传一份完整谱面。
3. 保存成功后，上传者及所有合作谱师各占用一个本届名额，并都能在「我的投稿」看到作品。默认上限为 1 时，任何一方都不能再独立投稿或被加入另一张合作谱。

授权本身不预占名额；一次授权仅用于指定上传者的一张合作谱。未使用的授权可以撤销，已用于投稿的合作关系不会由撤销授权修改。提交时会重新核对所有作者的名额和授权；并发请求只有满足限额的投稿会成功，失败请求会清理本次新上传的资源。

同一张谱面只计一次，即使该账号同时是上传者和共同作者。在「大小号合并计算」模式下，同组多个作者参与同一张谱面也只占一个名额。名额实时统计本届状态为「已投稿」的谱面；归档或删除谱面后释放所有参与作者的名额，比赛整体换届后重新计数。

评分仍按实际用户归并大小号身份。合作作者及其同组大小号都不会被分配自己参与的谱面，也不能通过额外评分提交。合作作者计入参赛人数并获得评分资格。只有上传者或具备谱面修改权限的管理员可以重试 Net 同步。

公开作品列表仅标记是否为合作谱，不公开合作账号名单；参与作者和有谱面查看权限的管理员可以查看作者账号。原有谱师名义、评分导出列和 Net 文件协议保持原有处理方式。

迁移 `0006_collaboration_and_submission_quotas` 增加这些配置和授权记录，不删除或重写已有投稿及文件；旧共同作者会计入名额。若现有账号已超过新上限，保留既有作品并拒绝继续新增。当前开发及测试继续关闭 Net 实网调用。

后台谱面详情提供「删除」，列表支持「删除所选的谱面」，均需删除权限并经过确认。已归档比赛仍为只读。删除会同时移除关联评分、评分任务和已使用的合作授权；重新合作投稿需重新授权。R2 原文件与已同步的 Net 副本不会自动删除。

投稿时曲名与谱师名义均为必填，前后端拒绝缺失、空值和纯空格；不再从谱面文件或用户名自动补全。

## 分配评分与导出

在进行中的比赛详情点击「预览 / 分配评分任务」。分配仅使用本届作品和投稿者，保留已有任务及评分，不给本人及其绑定账号参与创作的作品分配评分。

比赛详情中的「导出本届成绩」在归档后仍可使用，保留原有中文双工作表、评语、真爱票与去高低均分。谱面、歌曲、评分记录、评分任务和歌曲抽选列表支持按比赛筛选。

下载作品时，进入「本届谱面」，勾选需要的记录，选择「批量下载所选谱面（ZIP）」并执行。每张谱面放在独立的 `<谱面 GUID>/` 目录中，目录内保留上传时的原文件名，包括中文、空格和标点；`谱面列表.txt` 记录 GUID、标题和谱师名义。单谱下载仍生成可直接使用的 `maidata.txt`、`track.*`、`bg.*` / `pv.mp4` 布局。归档比赛同样支持下载。文件直接从 R2 读取，打包只使用自动清理的临时缓冲，不触发 Net 同步。若已引用的资源缺失或不可读，会提示对应谱面及文件类型，不返回不完整的压缩包。

## 归档比赛

在进行中的比赛详情点击「归档比赛」。确认页会显示谱面、歌曲和评分数量；确认后：

- 本届比赛及阶段、作品、抽选和评分变为只读，后台仍可查询并导出。
- 保留原数据库记录、作者关系、资源 key 和 R2 文件；不搬移或删除对象，不再次向 Net 上传。
- 新一届重新计算歌曲上传额度、评分任务和真爱票额度，旧记录不占用。
- 没有新的进行中比赛时，首页显示「暂无进行中的比赛」，投稿、歌曲功能和评分关闭。

归档入口不提供撤销。如果仍有 Net 同步正在进行，需先等待完成；异常中断的同步可用原有 `resolve_net_sync` 命令核对状态后再归档。投稿页面不再显示要求参赛者人工核对 Net 的提示，内部同步记录继续保留以避免重复上传。

## 现有数据迁移

迁移 `songs.0004_competition_lifecycle` 将原有比赛配置、阶段、歌曲和谱面归入一届「历史比赛」，状态为「已归档」。评分、任务、抽选结果通过原有作品和阶段关系归属该届。原字段内容、中文文案、用户与资源路径保持不变；完整谱面依旧保留 `submitted` 状态用于历史成绩导出，半成品依旧为 `archived`。

迁移后不会自动开启新比赛，需要管理员按上述步骤新建并启用。空库安装不生成虚构的历史比赛。原全站单例比赛配置表被移除，不保留运行时兼容层。

部署前备份 SQLite，并先在副本上验证。由于多届数据无法无损合并回旧的单例结构，回滚需要同时恢复迁移前数据库与对应代码。

## 谱面文件组织

新投稿在 R2 中保存为 `media/charts/<谱面 GUID>/<原文件名>`。同一张谱面的谱面文件、音频、封面和视频共用一个目录；GUID 由服务器生成，与客户端投稿重试标识分开，避免并发重试相互覆盖或误删文件。Net 协议需要的标准文件名在发送时处理，不改变 R2 中的名称。

历史谱面通过 `0005_chart_guid_assets` 补充 GUID，已有资源 key 保持不变；批量下载仍会统一组织为 GUID 目录，使用历史记录中的文件名。原上传名若已被旧版本改写，无法从当前记录恢复。
